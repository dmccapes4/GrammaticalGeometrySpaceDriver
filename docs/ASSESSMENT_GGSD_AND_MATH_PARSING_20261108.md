  - of his master (greekbible.com)
  - of his lord   (greekbible.com)

**Possible interpretations (set — not a choice) — five entries:** God / a human master or employer / a sovereign or ruler / divine sovereignty / "the genitive case suggests possession."

**All five are the same reading.** Lord-or-master, five times, with the referent varied.

The adjectival reading is **not in the set**. `κύριος` as an adjective — "having power or authority, valid, lawful, appropriate, sovereign" — is the reading the skill file states GGSD confirms from `logeion_parse`, and it is the reading the operator's decoding turns on. It does not appear.

### αὐτοῦ (report.md:453–467)

Five interpretations, all pronominal: the master's silver / the servant's action / the master's authority / the servant's responsibility / and this one, verbatim:

```
  - [inferred from training, not sourced] the silver belongs to the master,
    and the servant is acting under his authority
```

The adverb of place — **"in this very place", "just there", "just here"** — which the skill file attributes to `logeion_shortdef`, LSJ **and** Abbott-Smith, three witnesses, is **absent**.

### Why the audit trail did not catch it

`schema.py` is built to stop one thing: deleting a reading without a consented rule. `validate_primitive` (line 188) raises only if an elimination references an unconsented rule. On this run, `eliminations` is **empty** — so the file validates.

**Nothing was eliminated. The readings were never generated.**

```
The schema forbids subtraction.
The failure was in addition.
```

A set that was never populated cannot be audited for what was removed from it. The guarantee is real and it is guarding the wrong door.

### Two contributing causes, both fixable

1. **`greekbible.com` is counted as a witness.** It is a *translation*, not a lexicon. Five of five "translations standing" for κυρίου come from it, with zero lexical witnesses. A translation is a record of someone else's eliminations — importing it as a source imports the eliminations the tool exists to refuse.
2. **The model was asked to propose the set.** `empty_primitive` gives the model `possible_interpretations: []` to fill. Asked to propose readings for κυρίου, a language model returns the distribution of its training data, which is two thousand years of "lord." That is not a model defect; it is the wrong job to give a model. The readings are *in the parse data already*.

## III. The asset that makes the fix easy is already in the repo

`morphgnt/` is the strongest thing here and the pipeline does not use it for grammar.

**SBLGNT with full parse codes for every word in the New Testament:**

```

│      │  │        │                    └ lemma
│      │  │        └ surface / normalized / stripped
│      │  └ 8-slot morphology (person·tense·voice·mood·case·number·gender·degree)
│      └ part of speech
└ book·chapter·verse
```

**And a morphological lexicon:**

| File | Lines |
|---|---|
| `lexicon/forms.yaml` | 88,013 |
| `lexicon/projects/nominal_distinguishers/nominals.txt` | 9,963 |
| `lexicon/lexemes.yaml`, `derivation.yaml`, `ending_tree.txt`, `nominal-endings.txt` | — |
| `lexicon/projects/` — `citation_forms`, `derivational_morphology`, `principal_parts`, `preverbs`, `lemmatization_differences` | — |

**The grammar is a lookup, not an inference.** Which means:

- The v0.0.3 three-pass design (3N–4N model calls; 45–60 for this verse) asks a model to compute something the repo can compute exactly.
- Per `no-agentic-loops.mdc`, an LLM-filter → LLM-refilter → LLM-refilter architecture needs its three conditions written down before it is built. The deterministic path satisfies condition 1 (a hard oracle) for free, and removes the need for the other two by removing the loop.

The honest version of v0.0.3 is **smaller** than v0.0.2, not bigger: enumerate the parses from MorphGNT, enumerate the glosses from the lexica, take the product, and let code mark which combinations the parse code permits. The model's job shrinks to one thing it is actually good at — reading a dictionary entry and reporting what senses it lists, with the quotation.

### The tool in here that already has the right posture

`tools/sem_sim.py`, docstring:

> This is a pointing tool. The pointing was done by the operator. The tool measures whether the pointing holds in the embedding space. **It does not invent or rederive the pointing.**

That is the correct division of labour, stated by the tool about itself. Everything else should be built to that sentence.

## IV. "Mathematical parsing" splits three ways

The phrase could mean three different things and they have very different values.

### (a) Parse mathematical expressions into a syntax tree — **no**

Feed it `(λα²)μά`, get an AST. Twenty lines with `sympy.parse_expr`.

**Not useful, because parsing the expression is not the hard part.** The hard part is deciding what λ and μ denote, and that decision is the operator's and must stay his. Tonight proved this: the same expression was *worthless* with λ as wavelength and *exactly right* with λ as torsional stiffness. A parser is indifferent to that. It would build a calculator for a problem that is not arithmetic.

### (b) Dimensional analysis as an eliminating oracle — **yes, and this is the one**

See §V. This is the recommendation.

### (c) Set algebra over the witnesses — **yes, cheap, and it would have caught §II**

See §VI.

## V. Dimensional analysis is the first thing in GGSD that can legitimately eliminate

### The empirical case, from tonight

Two symbol readings were tested in one session:

| Expression | Symbols as assigned | Result | Verdict |
|---|---|---|---|
| `∫(λα²)μ dα` | λ = wavelength (m), α = rad, μ = linear mass density (kg/m) | **kg** | Claimed to be "total work done." It is a mass. **Fails** |
| `λα²` | λ = torsional stiffness (N·m/rad), α = rad | **N·m = J** | Claimed to be energy. It is energy. **Passes** |

**The thing that discriminated them was units.** Not judgement, not consensus, not a model. A unit table.

And note what it caught: a confident, fluent, well-formatted answer from a frontier model, presented in prose with a table and a numbered loop, which was wrong on its own definitions. Nothing else in the session caught that. The check took one line of arithmetic.

### Why it fits the existing schema exactly

`schema.py` already has the machinery and it has never fired:

```python
make_rule(category, value, source_id, quotation, status="proposed"|"consented")
make_elimination(translation, rule_id, source_id, quotation)
# validate_primitive: an elimination MUST reference a consented rule
```

The `eliminations` field has sat empty because **no source in Logeion can eliminate a lexical reading.** LSJ listing a sense is not grounds to strike another sense. That is correct, and it is why the field is unused.

Mathematics is different. A dimensional mismatch is:

- **a rule** — "energy has dimension M·L²·T⁻²"
- **with a source** — the SI base-quantity table
- **with a quotation** — the dimension string itself
- **and it is consented** in the strongest sense available: it is not an opinion about Greek, it is a constraint the operator already accepts

```
source_id:  "si_dimensions"
rule:       "energy = M·L²·T⁻²"
quotation:  "J = kg·m²·s⁻²"
status:     "consented"
elimination: "∫λα²μ dα as energy — computed dimension M, expected M·L²·T⁻²"
```

**That is the first elimination in this project that is not an act of interpretation.** It cannot smuggle in a theological preference, because it does not know what the words mean. It only knows whether the bookkeeping closes.

### What it would be

A `dimensions.py`, roughly 100–150 lines over `pint` or `sympy.physics.units`:

```
Input:   expression string + {symbol: unit} assignment + claimed quantity
Output:  computed dimension
         PASS | FAIL
         on FAIL: an elimination record naming the mismatch
```

Three properties worth stating plainly:

1. **It is an oracle, not a loop.** No model reasons about another model's output. `no-agentic-loops.mdc` does not apply because there is no loop to guard.
2. **It is cheap.** Microseconds, no API, no GPU, runs in CI.
3. **It fails loudly and specifically.** "Computed M, expected M·L²·T⁻²" is a sentence a person can act on.

### Its limits, stated

- It cannot tell him λ *is* torsional stiffness. It can only tell him that if λ is torsional stiffness then `λα²` is an energy, and if λ is a wavelength then it is not.
- Dimensional consistency is **necessary, not sufficient.** `½κθ²` and `2κθ²` both pass. It finds wrong *kinds*, not wrong *coefficients*.
- It says nothing whatsoever about whether the Greek means what he reads it as. It is a check on the physics claim downstream of the reading, not on the reading.

That third limit is the important one, and it is why this is a good addition rather than a dangerous one: **it cannot be used to adjudicate the Greek.** It only audits the arithmetic that someone attaches to the Greek. The two stay separated, which is the thing the schema was built to protect.

## VI. Set algebra over witness classes — cheap, and it would have caught §II

`compute_agreements` (schema.py:152) already tallies which `source_id`s agree on a value and sets `agreement: len(source_ids) >= 2`. It is half of a useful thing. The missing half is that **sources are not interchangeable**, and the κυρίου failure is exactly a witness-class pathology.

Add a class to each source and three computed quantities:

```python
SOURCE_CLASS = {
    "logeion_lsj":        "lexicon",
    "logeion_abbott_smith":"lexicon",
    "logeion_parse":      "parse",       # deterministic morphology
    "morphgnt":           "parse",
    "greekbible_com":     "translation", # someone else's eliminations
}
```

| Quantity | What it catches |
|---|---|
| **Witness-class imbalance** — a reading supported by ≥1 translation and **0** lexicon sources | κυρίου on this run: 5 translation witnesses, 0 lexicon. **Would have fired** |
| **Parse-set coverage** — every parse the morphology permits should appear in ≥1 interpretation | κυρίου's adjectival parse and αὐτοῦ's adverbial sense are both permitted and both missing. **Would have fired on both** |
| **Set cardinality per word** — |interpretations| and its collapse across passes | Makes "the set is open" a number instead of a bullet list |

That second one is the real prize, and it is a **completeness check rather than a consistency check** — the thing §II needed and nothing in the tool provides. It is computable from data already on disk, with no model call.

Roughly 150 lines. It is the highest value-per-line change available.

## VII. Ordering, and the one thing I would not build

**The analysis layer goes on last.** A dimensional-analysis module and a set-algebra module sitting on top of a set that is missing the readings he cares about would make the §II failure *harder* to see, not easier — a richer report over the same gap, with more numbers certifying it. Fix generation first.

| Order | Change | Size |
|---|---|---|
| 1 | **Parse-set coverage check.** Assert every morphologically permitted parse appears in ≥1 interpretation. Fail the run if not | small |
| 2 | **Witness classes.** `greekbible.com` stops counting as a lexical witness | small |
| 3 | **Generate the set from data, not from the model.** MorphGNT parses × lexicon glosses; model reports what an entry says, with the quotation, and does not propose readings | medium |
| 4 | **De-fork.** One copy, symlink or import the other. Fix the three version strings | trivial |
| 5 | **`dimensions.py`.** The eliminating oracle | small |
| 6 | Witness-class metrics and set cardinality | small |

**What I would not build: the v0.0.3 three-pass LLM filter.** 45–60 model calls to compute a grammatical constraint that `morphgnt/` already answers exactly. The gameplan's own defence is "This is expensive compared to v0.0.2's 1 model call per word. It is correct. A fast wrong answer fills the file and looks finished." The first and third sentences are right. The second is the one to check — and §II is a fast wrong answer that filled the file and looked finished, produced by the *cheap* architecture, so expense is not what fixes it. Determinism is.

## VIII. Direct answers

**Is it useful enough to help us here?**

**Not as built, on the evidence of the run I read** — it returned the KJV reading on κυρίου and αὐτοῦ, which are the two words the project is about, and the validator passed the file. **As designed, yes**, and the gap between the two is addition, not subtraction: the schema guards against removing readings and nothing guards against never producing them.

What would make it useful tonight is item 1 in the table — a coverage assertion. One check, and the run I read would have failed instead of reporting a clean set.

**Could we add mathematical parsing?**

Expression parsing: yes trivially, no value. **Dimensional analysis: yes, and it is the most valuable addition available, because it gives the `eliminations` field its first legitimate use.** Every elimination in GGSD so far would have been an interpretive act, which is why the operator correctly forbade them. A unit mismatch is not an interpretive act. It is the only kind of elimination this tool can honestly make.
